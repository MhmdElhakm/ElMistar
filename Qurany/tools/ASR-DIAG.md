# قياس أداء التسميع (المرحلة الثانية)

الهدف: قياس لا إصلاح. لا يغيّر النموذج ولا المطابقة ولا سلوك التسميع. كل شيء معطّل افتراضيًا ومحلي بالكامل.

## ما الذي يُقاس (مباشر) وما الذي لا يُقاس
| الحقل | المصدر | ملاحظة |
|---|---|---|
| libMs | `performance.now()` حول `import()` للمكتبة | تحميل المكتبة من CDN |
| pipelineMs | حول `pipeline()` | تنزيل + تجميع، لا يمكن فصلهما من الواجهة الحالية |
| bytes | مجموع `total` من أحداث التقدم | 0/غير مقاس إن قُرئ من الكاش |
| inferMs | قبل/بعد `transcribe()` | الاستدلال وحده؛ «بارد» = أول استدلال بعد التحميل |
| queueWaitMs | من وضع المقطع بالطابور حتى بدء معالجته | |
| matchMs | زمن `feedTasmeeText` | المطابقة فقط |
| paintMs | إطاران `requestAnimationFrame` بعد المطابقة | تقريب لأقرب عرض، لا لحظة وصول الضوء للعين |
| e2eMs | من آخر إطار صوتي وصل للمقطع حتى الرسم | |
| e2eVoiceMs | من آخر إطار فيه كلام حتى الرسم | يشمل 700ms نهاية الكلام في المقاطع النهائية (بالتصميم) |
| frames / stalls / maxGapMs | فجوات بين استدعاءات الالتقاط (>3× الإطار = توقف) | مؤشر لضغط الخيط الرئيسي وليس فقدان مؤكدًا |
| droppedInterim / stale | عدّادات سياسة الطابور الحالية | مؤقت أُسقط لأن المعالج مشغول / نتيجة قديمة أُهملت |
| rejectedHallu | النص الخام غير فارغ والمرشّح أعاده فارغًا | |
| advanced | عدد الكلمات المكشوفة زاد بعد المطابقة | |
| heapMB | `performance.memory` | كروم فقط، وإلا فارغ |
| constraints | `track.getSettings()` | القيم الفعلية التي قبلها المتصفح |

**غير مقاس:** لحظة النطق الفعلية، زمن الميكروفون ومخرج الصوت، حرارة الجهاز والبطارية (لا واجهة لها؛ دوّنها يدويًا في الجدول). المحرك الفعلي: مطلوب wasm؛ المقروء فقط عدد الخيوط. لا يوجد تحقق مباشر.

لا يُخزَّن صوت ولا نص تلاوة، فقط أزمنة وعدّادات وأطوال (rawChars/textChars). السجل في `localStorage` تحت `mq.asrDiagLog` (آخر 400 مقطع).

## التشغيل
1. افتح التطبيق ← الإعدادات ← «طريقة التعرّف في التسميع» ← فعّل «تشخيص الأداء». (أو أضف `?asrdiag=1` للرابط.)
2. اختر «النموذج القرآني» ونزّله (يعرض التطبيق التقدم). أعد فتح التطبيق إن لزم.
3. نفّذ السيناريوهات أدناه، ثم افتح اللوحة وصدّر JSON أو CSV.

## سيناريوهات الهاتف (كل سيناريو في جلسة تسميع منفصلة؛ أعد تعيين السجل بين الأجهزة)
**أ. قراءة صحيحة:** سورة الفاتحة كاملة بسرعة عادية، 3 مرات. سجّل: بارد/مستقر، حرارة (دافئ/ساخن بعد 5 دقائق).
**ب. خطأ متعمد:** اقرأ آية وأبدل كلمة بأخرى، ثم اقرأ آية وتخطَّ كلمة. المطلوب: ألا تُكشف الكلمة غير المنطوقة. دوّن كل حالة كشف خاطئ أو رفض خاطئ يدويًا (التطبيق لا يعرف الحقيقة المرجعية).
**ج. صمت:** ابدأ التسميع واترك الهاتف 60 ثانية صامتًا (ثم 60 ثانية مع ضوضاء غرفة). المتوقع: لا مقاطع ولا كلمات. دوّن عدد المقاطع المسجّلة وأي كشف.
**د. قراءة مستمرة 3 دقائق:** البقرة أو أي سورة طويلة بلا توقف. انظر في اللوحة سطر «انتظار الطابور: أول ثلث ← آخر ثلث» و«مؤقتة مُسقَطة» و«أطول فجوة». ارتفاع زمن الاستدلال مع طول المقطع أو ازدياد الانتظار يعني تراكم تأخير.
**هـ. مختبر منفصل:** افتح `/tools/asr-lab.html` من نفس العنوان. نزّل النموذج، سجّل 10 ثوانٍ، وشغّل «اختبار التراكم» و«الصمت والضوضاء». ثم أعد التسجيل بإيقاف ضبط الضوضاء/AGC لمقارنة الأثر على الدقة (قارن فقط، لا تفترض).
